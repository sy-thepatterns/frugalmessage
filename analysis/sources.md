# Dataset register

| ID | Source and original link | Author / period | Fields and scale | Intended use | Boundary |
| --- | --- | --- | --- | --- | --- |
| INTEL-2004 | [Intel Lab Data](https://db.lcs.mit.edu/labdata/labdata.html) | Intel Berkeley Research Lab team; 28 Feb-5 Apr 2004 | About 2.3 million timestamped readings from 54 motes: epoch, mote ID, temperature, humidity, light, voltage; published connectivity probabilities separately | Analysis I: temporal demand and missingness; replay input for controlled batching experiments | Wireless readings, not internal server packets or power. The log has missing epochs and incomplete motes. Original page permits reuse with acknowledgement. |
| ALIBABA-MS-2021 | [Alibaba cluster-trace-microservices-v2021](https://github.com/alibaba/clusterdata/tree/master/cluster-trace-microservices-v2021) | Alibaba; 12 hours in 2021 | Service call graphs (0.5% sample, >20 million call graphs), upstream/downstream service IDs, RPC type, response time; call-rate metrics, CPU and memory for part of fleet | Analysis I: fan-out, call paths, traffic concentration, response-time distributions | Anonymized; sampled call graphs, mixed scopes, no direct watts or per-edge payload bytes. Archives are tens of GiB. |
| AZURE-FUNC-2019 | [Azure Functions Trace 2019](https://github.com/Azure/AzurePublicDataset/blob/master/AzureFunctionsDataset2019.md) | Microsoft; July 2019 | 14 days of per-minute invocation counts and trigger classes, daily duration summaries | Analysis I: burstiness and quiet periods; experiment arrival schedules | Function invocations are not inter-service calls; release is a small, unspecified sample. CC BY. |
| GOOGLE-BORG-2019 | [Google cluster data 2019](https://github.com/google/cluster-data/blob/master/ClusterData2019.md) | Google; May 2019 | Eight cells, month-long CPU usage histograms and resource requests | Analysis I: resource-utilization context | No inter-service access patterns; 2.4 TiB compressed via BigQuery. CC BY. |
| GOOGLE-POWER-2019 | [Google PowerData 2019](https://github.com/google/cluster-data/blob/master/PowerData2019.md) | Google; May 2019 | Power utilization of 57 power domains | Analysis I: whole-system power context | Aggregated domains cannot attribute joules to one message or configuration. CC BY. |
| SPECPOWER | [SPECpower_ssj2008 results](https://www.spec.org/power_ssj2008/results/power_ssj2008/) | SPEC / submitters; published results | Measured server watts and operations/s at multiple loads, including idle | Sensitivity bounds for hardware power models | Java workload and disclosed machines; cannot be reused as measured MQTT/HTTP energy. Respect SPEC fair-use rules. |
| OTEL-DEMO | [OpenTelemetry Demo](https://github.com/open-telemetry/opentelemetry-demo) | OpenTelemetry contributors; version must be pinned at experiment time | Reproducible HTTP/gRPC/queue service topology and load generator; traces and metrics produced by our runs | Analysis II: controlled configuration comparisons | A benchmark application, not a ready-made energy dataset. Record version, hardware, workload and instrumentation overhead. |

Sources are observational data or potential experimental inputs. We must never present a replay, a simulated batching result, or a SPEC power curve as measured energy savings for FrugalMessage.
